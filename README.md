# 学園祭 売店ゴミ回収 管理アプリ

学園祭「かまた祭 2026」で、施設管理スタッフが各売店（28店）のゴミ回収状況をスマホで記録・共有するための Web アプリです。
本番の2日間（2026年10月31日・11月1日）に、実際にスタッフが使いました。

- 制作期間：2026年10月（約2週間）
- 担当：要件決め・設計・実装・テスト・公開・本番運用、スタッフ向けの資料づくりまで一人で担当
- 開発の進め方：AI コーディングツール（Claude Code）を使って開発しました。何を作るか、どういう仕組みにするか（下の「工夫したところ」）は自分で決め、AI にはコードを書く作業を手伝ってもらっています

## なぜ作ったか・どう変わったか
これまでは、集積所に持ち込まれたゴミがどの売店のものか分からず、分別も施設管理のスタッフが自分たちでやり直していたため、毎日20時ごろまで作業が続いていました。

このアプリで、

- どの売店がゴミを持ってきたか
- ルールどおりに分別できていたか（できていなければ差し戻し）
- まだゴミを出しに来ていない売店はどこか

がスタッフ全員のスマホで一目で分かるようになりました。その結果、**片付けの作業が約2時間早く終わる** ようになり、スタッフの仕事も「自分たちで分別する」から「売店が分別できているかを確認する」だけになりました。

## できること
- 店ごとの記録：**回収OK／差し戻し／ゴミ袋の配布（枚数）／本日終了**。まちがえた記録は取り消せる
- 全体のメモと店ごとのメモ（引き継ぎや注意点の共有）
- その日の記録をまとめた **報告書**（印刷して PDF で保存）
- 本番前に練習できる **練習モード**（本番の記録とは混ざらない）
- 各自のスマホから5秒ごとに最新の状況を取りに行くので、ほかのスタッフの記録がすぐ反映される
- ホーム画面に追加してアプリのように使える（Web アプリのマニフェスト）

## 所属ごとの権限
名前の後ろに所属を付けて入力し（例：`山田花子（施設管理）`）、所属でできることを分けています。

| 所属 | 記録・取り消し・店名の変更 | メモ | 報告書 |
|---|---|---|---|
| 本部・教員 | ○ | ○（だれのメモでも取り消せる） | ○ |
| 施設管理 | ○ | ○（だれのメモでも取り消せる） | 担当者のみ |
| 売店部 | ×（見るだけ） | ○（自分のメモだけ取り消せる） | × |
| 所属なし | ×（見るだけ） | × | × |

画面のボタンを隠すだけでなく、**サーバー側でも同じ判定をして、権限がなければ 403 で断る** ようにしています（`server/roles.js`）。

## 使った技術
- フロントエンド：React 19 / Vite
- サーバー：Netlify Functions（Node.js）
- データベース：Supabase（PostgreSQL）。パソコンの中で試すときは PGlite
- テスト：Node.js 標準のテストランナー（38件）

## 工夫したところ

### 1. 同時に押されても数がくずれない
記録には「1店・1日150件まで」の上限を付けています（いたずらや誤操作で記録が増え続けないように）。
何人かが同時に記録しても上限を超えないことを、同時送信のテストで確かめています。取り消しを2回押しても、最初に取り消した時刻と人がそのまま残ります。

### 2. だれが取り消したかを残す
記録やメモを取り消すと、取り消した人と時刻を残し、画面に「取り消し済み（名前・所属・時刻）」と表示します。あとから「なぜ消えたのか」を確かめられるようにするためです。

### 3. 本番中にデータベースを安全に変える
機能を足すたびに、表を作り直すのではなく **追加分の SQL（`db/migrations/`）** を用意しました。すべて「何度流しても壊れない」書き方にし、テストでも2回流して確かめています。

### 4. 使った人数を数える（個人は特定しない）
「その日何台のスマホで使われたか」を、スマホごとのランダムな番号で数えています。合言葉を知っている人だけが `/admin` で見られます。

### 5. 作って終わりにしない
スタッフ向けに、仕様書・技術書・制作手順書・引き継ぎ書・使い方マニュアルの5つの資料を作り、来年以降の後輩が引き継げるようにしました。

## 割り切ったところ
ログイン機能はなく、**URL を知っている人だけが使える** 形にしています。所属は自己申告なので、なりすましは防げません。
学園祭の2日間だけ、学内のスタッフ数人が使う道具なので、ログインの手間よりすぐ使えることを優先してこの形にしました。
もっと長く・大勢で使うなら、ログイン機能とサーバー側での本人確認を入れるべきだと考えています。

## パソコンで動かす

```sh
npm install
npm start   # http://localhost:8788 で起動（データベースは PGlite を使うので準備不要）
npm test    # テスト（38件）
```

報告書を出せる担当者の名前は、`.env.local` に `VITE_REPORTERS=名前1,名前2` の形で書きます（実名を公開しないため、このリポジトリには含めていません）。

本番（Netlify + Supabase）では、Supabase の SQL Editor で `db/schema.sql` を実行し、Netlify の環境変数 `DATABASE_URL` と `ADMIN_PASSWORD` を設定します。
